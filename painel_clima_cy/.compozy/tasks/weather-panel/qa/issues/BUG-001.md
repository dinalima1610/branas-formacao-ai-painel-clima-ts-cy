# BUG-001: Mobile forecast page overflows horizontally after weather loads

**Impact (user-side):** Friction
**Severity:** High
**Priority:** P2
**Type:** UI
**Status:** pending
**Persona Affected:** Mobile User
**Journey Step:** J-02 Use current location after explicit opt-in, Step 5 (review loaded weather)

## Environment

- **Build:** Frontend production build refreshed on 2026-05-21T23:28:57-03:00 and served by Vite preview at `http://127.0.0.1:4173/`; backend reachable at `http://localhost:3000`; CI status not independently confirmed.
- **OS:** Microsoft Windows 11 Pro 10.0.26200
- **Browser:** Playwright Chromium 1.60.0
- **Viewport:** 375 x 812
- **Network:** wifi-fast
- **Locale:** pt-BR
- **URL:** `http://127.0.0.1:4173/`

## Summary

A mobile user can complete the weather journey, but after loading forecast results the document becomes much wider than the 375px viewport. The user sees a narrow left slice of a 2600px-wide page and can horizontally pan the whole document, which makes the forecast feel broken on the PRD's mobile-first surface.

## Reproduction

Charter: CH-01
Tour: Network Tour

Steps:

1. Open the app at `http://127.0.0.1:4173/` with a 375 x 812 viewport.
2. Click `Usar minha localização` and allow geolocation.
3. Wait for weather results to load.
4. Inspect the loaded page width and the mobile screenshot.

Observed:

- Browser evidence recorded document scroll width `2600px` against a `375px` client width.
- Screenshot: `qa/screenshots/task05-j02-03-location-forecast.png`

## Expected

The page should remain constrained to the mobile viewport. Any horizontal scrolling should be limited to the hourly forecast strip, not the entire document.

## Root cause

Unknown. The overflow appears after forecast content renders, likely from an element whose intrinsic width escapes the mobile layout.

## Fix

Pending engineering triage.

- Re-run `TC-JOURNEY-002` at 375 x 812.

## Impact

- **Users Affected:** Mobile users on the forecast results surface.
- **Frequency:** Always observed in this QA run after mobile forecast results loaded.
- **Workaround:** User can pan horizontally, but this is awkward and easy to misread.
- **Trust cost:** The page appears not to be designed for the mobile viewport even though mobile-first behavior is part of the MVP.
