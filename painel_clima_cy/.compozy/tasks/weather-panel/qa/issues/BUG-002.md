## Summary

After a user grants location permission, the forecast loads but the place label reads `Local atual (-23.55, -46.63)` instead of a human-readable city or locality. The user receives weather data but cannot confidently tell which place the app resolved, weakening trust in the geolocation flow.

## Reproduction

Charter: CH-01
Tour: Network Tour

Steps:

1. Open the app at `http://127.0.0.1:4173/` with a 375 x 812 viewport.
2. Click `Usar minha localização`.
3. Allow geolocation for coordinates near São Paulo.
4. Review the place label in the current conditions panel after the forecast loads.

Observed:

- Current conditions label displays `Local atual (-23.55, -46.63)` rather than a locality name.
- Screenshot: `qa/screenshots/task05-j02-03-location-forecast.png`

## Expected

The geolocation journey should show a readable place label after explicit opt-in, or present clear recovery guidance if reverse geocoding cannot produce a locality.

## Root cause

Likely tied to the backend reverse-geocoding coordinate fallback when the upstream reverse endpoint is unavailable or returns no useful locality. Engineering should confirm before fixing.

Pending engineering triage.
